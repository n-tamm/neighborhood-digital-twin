# 13. Capstone Delivery

The final release must connect the repository, analysis, report, and demonstration to the same reproducible evidence.

## Required repository evidence

- root README with accurate commands for running the code;
- `pyproject.toml` containing all and only the libraries the project uses;
- code that generates reported results, tables, and figures;
- relative paths, no committed credentials, and no unused code or files;
- data access, ownership, licensing, and redistribution notes;
- inline source links and license review for copied or adapted code.

## Required report evidence

The report should remain under 3,000 words when practical and include:

- a project statement for a broad audience;
- justified methodology and evaluation strategy;
- technical depth drawing from multiple MADS areas;
- interpretation of numerical results;
- affected groups and at least one ethical concern;
- at least three original, legible, code-generated visualizations;
- at least three relevant external sources with consistent citations;
- each team member's contribution;
- evidence that major mentor feedback was addressed.

Because AI has been used, `reports/AI_USAGE_APPENDIX.md` must document the workflow and diagram, models and available parameters, prompt-composition approach with an actual prompt, and output evaluation with an actual evaluation.

## Reproducibility check

A reviewer should be able to:

1. create the supported environment;
2. run tests without downloading the full national dataset;
3. reproduce a small end-to-end example;
4. run the documented commands that generate final results and figures;
5. match application outputs to the released data and model versions.

If the full pipeline is too large for a review run, include a small legally redistributable fixture and exact instructions for running the full process. Do not substitute an undocumented prepared file for a reproducible path.

## Final checks

- [ ] README commands work from a clean checkout.
- [ ] Dependencies match imports and required development tools.
- [ ] Final data, feature, model, and application versions are fixed.
- [ ] The locked evaluation uses untouched temporal and geographic test sets.
- [ ] Report numbers and application numbers match generated outputs.
- [ ] Every final figure and table is generated by documented code.
- [ ] Source terms, attribution, citations, and privacy have been reviewed.
- [ ] Secrets, absolute personal paths, raw restricted data, and unused files are absent.
- [ ] AI appendix and team contribution statement match the final work.
- [ ] The three-to-five-minute video or poster and gallery post are complete.
