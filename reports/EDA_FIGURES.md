# EDA Figures

The project has a completed first visual-EDA pass and an expanded twelve-figure workflow. The
PNGs are generated by
the Databricks `visual_eda` job and saved in a versioned Unity Catalog managed volume rather than
committed as changing binary files in Git.

  `workspace.neighborhood_twin_gold.gold_eda_figure_manifest`

The manifest is the authoritative way to find a matched figure set. It records each figure's
order, stable name, title, intended use, volume path, file type, byte size, and build ID. A newer
successful run will replace the current manifest while retaining prior versioned directories.

## Visual and map design

The map code is original to this repository. It uses thin or absent tract outlines, stronger
county boundaries, a dedicated missing-data gray, consistent scales across pilot states, and
separate county and tract views. Ordered coverage uses a perceptually ordered sequential palette;
HPI change uses a zero-centered diverging palette because zero has a real analytical meaning.
That choice follows [Matplotlib's colormap guidance](https://matplotlib.org/stable/users/explain/colors/colormaps.html),
which distinguishes ordered sequential data from values that diverge around a meaningful center.

County display shapes are dissolved from the approved tract display geometry with
[Shapely `union_all`](https://shapely.readthedocs.io/en/latest/reference/shapely.unary_union.html).
They remain display-only and must not be reused as analytical adjacency or distance geometry. The
overall idea of pairing a map with supporting analytical context is inspired by the
[Opportunity Atlas](https://opportunityatlas.org/); no Opportunity Atlas code or visual assets
were copied.

## Reproduce the figures

The job is defined in [`databricks.yml`](../databricks.yml). It runs these notebooks in order:

1. [`02_build_visual_eda.py`](../notebooks/04_exploration/02_build_visual_eda.py) publishes the
   governed summary tables.
2. [`03_render_eda_figures.py`](../notebooks/04_exploration/03_render_eda_figures.py) renders the
   twelve PNGs and publishes the manifest.

From the configured repository environment:

```powershell
databricks bundle validate -t team
databricks bundle deploy -t team
databricks bundle run visual_eda -t team
databricks bundle run table_metadata_pipeline -t team
```

The metadata job is rerun because the EDA job overwrites its current Delta summary tables.

## View or export a build

In Databricks Catalog Explorer, open the `workspace` catalog, then the
`neighborhood_twin_gold` schema and `eda_figures` volume. The current manifest can also be queried
from the SQL editor.

For local report assembly, copy the build named in the manifest into the ignored
`reports/generated/` directory:

```powershell
databricks fs cp `
  "dbfs:/Volumes/workspace/neighborhood_twin_gold/eda_figures/build_id=<BUILD_ID>" `
  "reports/generated/eda/<BUILD_ID>" `
  --recursive --overwrite -t team
```

Do not use `personal_scratch/` for these exports. It is reserved for material outside the tracked
core project or work the user explicitly assigns there.

Generated images are kept out of ordinary Git history because the rendering code, governed source
tables, manifest, and versioned Databricks files provide the reproducible record. When the final
report or presentation is assembled, the team can intentionally select a small approved set for
the submission package without committing every intermediate render.
